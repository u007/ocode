# TypeSafe auto-permission: durable judge log, compound-command scope guard, verify-before-floor

**Status:** Draft · **Created:** 2026-09-30
**Tracked at:** `TODO.md` → "Compound / substituted bash commands bypass EVERY deterministic scope check"

## Context

A read-only compound bash command was auto-denied: the judge returned an `allow` choice at
confidence **0.21** against the 0.85 floor. (Notation: that is a verdict plus a score, not a
package name.) Live probing of the real rubric — 30+ calls against `jev-latest`, rubric text
extracted verbatim from source — ruled out the command *shape*: the same command scores an
`allow` at **1.00** when the working directory sits inside `allowed_roots`, and 0.92–1.00 across
real-newline, populated-context, and populated-prefix-list variants. n=3 per case, single model
alias, so this is a negative result, not a bounded measurement.

The original event is **unrecoverable**. No persisted log holds it (searched both project session
stores — 500 and 1455 session DBs — plus all 182 session files modified today; zero hits outside
the transcript of the conversation that quoted it), and the `allowed_roots` in force were never
recorded anywhere.

Investigation did find a structural gap, verified by reading code rather than inference:

- `shellCompound` (`internal/agent/permissions.go:4849`) reports true for any command containing
  `&&`, `||`, `;`, `|`, a backtick, `$(`, `>`, or `<`.
- That makes `canAutoAllowInRoot` return false (`:4929`) and `firstOutOfScopePath` return `""`
  (`:4989`).
- Therefore `req.OutOfScopePath` is never populated, and `verifyAutoGrant`'s scope guard
  (`internal/agent/agent.go:4112`; was `:4051` before a concurrent session added ~60 lines to
  that file — re-grep before citing) is **structurally unreachable** for compound commands.
- Such a command takes a generic bash Ask, and the judge's reading of scope is the only scope
  signal before a human.
- Compounding it, the confidence floor returns at `internal/agent/permission_typesafe.go:310`
  while `verifyAutoGrant` runs at `:291` — so a below-floor allow is returned **unverified**.

The bail inside `firstOutOfScopePath` is deliberate: a substitution's path is runtime-only, so a
static path would falsely reject. The gap is a consequence of that choice, not a mistake in it.

## Change 1 — Durable judge-decision log

**Why first:** the whole investigation was archaeology because nothing survives the process. The
existing `emitDebug("PERMISSION", …)` verdict line reaches only the TUI or stderr.

**Reuse, do not rebuild.** `MirrorKindToFile` (`internal/debuglog/mirror.go`) already provides a
durable, per-kind, append-only sink with 2 MB single-generation rotation, and its documented
motivation is this exact problem. It is registered for `COMPACT` and `TOKENS` in
`internal/tui/model.go`.

**Design decision driven by the collision table:** register the new mirror from inside the judge
path (a `sync.Once` in a new file under `internal/agent`), not from `tui/model.go` or
`server/handler.go`. This avoids the two hottest files entirely and gets uniform behaviour in
TUI, server, and headless modes — which the current TUI-only registration does not.

**Do:**

1. New entry kind `PERMJUDGE` in `internal/debuglog/debuglog.go` (currently clean — low risk).
2. New file under `internal/agent` that registers the mirror to
   `<logsDir>/permission-judge.log` on first judge use, via a one-shot guard.
3. Emit one structured record per verdict from `askPermissionModelTypesafe`, carrying what is
   missing today: session id, tool, command, `working_directory`, `allowed_roots`, rule, concern
   and concern confidence, choice, confidence, the full `probabilities` map, the floor applied,
   and the final outcome (granted / deferred-below-floor / denied / guard-refused, naming which
   guard). Keep the existing summary line; add the record rather than replacing it.
4. Apply the same masking the judge request already uses (`judgeMaskRegistry`, `redactText`,
   `redactFileText`) so masked values are never written in clear. Growth is already bounded by
   the 2 MB cap, and mirror write failures report once without recursing.

**Verify:** a real bash command through ocode produces a record containing `allowed_roots` and
the outcome; a deliberately masked secret appears only as its mask token; the file rotates at the
cap.

## Change 2 — Deterministic scope check for compound commands

**Invariant — the reason this is safe:** it can only *add* human asks. `OutOfScopePath` is
consumed by `verifyAutoGrant` to **refuse** a grant, by `IsOutOfScopePathRequest` to classify,
and by `OutOfScopePathRoot` to offer persisting a root (`internal/agent/permission_paths.go`).
No consumer widens access. Over-detection yields an extra prompt; under-detection reproduces
today's behaviour. No path creates an unsafe grant — assert that in a test, do not trust it.

**Do:**

1. New file for the resolver, reusing existing helpers rather than re-parsing: `parseShellCommandLine`
   for segments, `extractBashCommandPaths` per segment, `expandBashForJudge`
   (`permission_shellvars.go`) for variables and substitutions.
2. Track `cd` targets **sequentially** to derive the effective working directory per segment.
   The current code resolves every path against a single `pm.workDir`, which is wrong the moment
   a command changes directory.
3. Claim a resolved path set **only when the expander's `opaque` set is empty**. Otherwise return
   nothing and preserve today's generic ask.
4. Populate `OutOfScopePath` for compound bash asks from this resolver. Leave `firstOutOfScopePath`
   as the fast path for simple commands, behaviour unchanged.
5. An unresolved `cd` into an unknown directory must **not** count as in-scope; return nothing so
   the status quo ask stands.

**Non-goal:** no sandboxing, no command rewriting. Scope detection only.

**Watch for:** over-detection on ordinary work. A false `OutOfScopePath` on
`for f in drizzle/*.sql; do … done` would prompt on a routine command. Globs must resolve against
the effective working directory, and a not-yet-existing target must count as in-scope.

**Verify:** a compound command with an out-of-scope `cd` sets `OutOfScopePath`; a fully in-scope
compound command does not; an opaque substitution yields the status quo.

## Change 3 — Verify before reporting below-floor

**Why:** a below-floor allow returns before any deterministic guard runs, so the banner attributes
everything to model confidence and hides which guard would have spoken.

**Do:** in `askPermissionModelTypesafe`, run `verifyAutoGrant` **before** the floor comparison.
Outcome is unchanged in both directions — a guard refusal and a low score both defer to a human
and `consulted` stays true — but the reason must now name what actually happened, and must lead
with the guard refusal when it fires, since that is the stronger reproducible signal.

**Verify:** the existing below-floor test in `permission_typesafe_test.go` is updated, not removed;
a new case asserts that guard-refusal plus low-confidence names both.

## Non-goals

- Do **not** lower `permissions.auto.min_confidence`. It would not have auto-granted the original
  call, correctly, and it weakens gates that matter.
- Do **not** switch the gate to `probabilities[choice]`. The measured gap is 0.00 in the confident
  band and only opens under uncertainty; for the out-of-roots case `p_allow` (0.29) sat *below*
  confidence, so the switch is more permissive for allows. That needs a labeled corpus first.
- Do not edit the rubric wording — the probe showed shape is not the cause.
