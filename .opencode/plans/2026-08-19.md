# Docker Cross-Compilation for ocode Desktop

## Goal
Build ocode desktop binaries for Linux and Windows from macOS using Docker.

## Current State
- Server binary (`go build .`) — pure Go, no CGO, cross-compiles with `GOOS`/`GOARCH` trivially
- Desktop binary (`go build ./cmd/ocode-desktop`) — imports Wails v3, needs CGO + native SDKs
- Wails v3 only imported by `cmd/ocode-desktop/` (main.go, native.go)
- Web frontend built with `pnpm` (not npm), Vite
- Existing `Dockerfile` builds server-only binary for Alpine
- No existing cross-compilation infrastructure

## Target Tuples
| Binary | Target | CGO | Docker base | Key deps |
|--------|--------|-----|-------------|----------|
| Server | linux/amd64 | No | Alpine | Go, Node, pnpm |
| Desktop | linux/amd64 | Yes | Ubuntu 24.04 | Go, Node, pnpm, webkit2gtk-4.1-dev, libgtk-3-dev |
| Desktop | windows/amd64 | Yes | Ubuntu 24.04 | Go, Node, pnpm, mingw-w64, gcc-mingw-w64 |
| Desktop | linux/arm64 | Yes | Ubuntu 24.04 | Same as linux/amd64 + cross-compile toolchain |

## Files to Create
1. **`Dockerfile.cross`** — Multi-stage, multi-target Dockerfile
2. **Makefile additions** — `docker-release`, `docker-desktop-linux`, `docker-desktop-windows` targets

## Architecture
```
Dockerfile.cross stages:
  ┌─ web-builder: Node 22 + pnpm ci + vite build (shared by all targets)
  ├─ go-mod-cache: Pre-download Go modules (shared)
  ├─ linux-desktop: Ubuntu 24.04 + webkit2gtk + Go → ocode-desktop-linux-amd64
  ├─ windows-desktop: Ubuntu 24.04 + mingw-w64 + Go → ocode-desktop-windows-amd64.exe
  └─ output: Copy all artifacts to /output
```

Build invoked via:
```bash
# All desktop targets
make docker-release

# Single target
docker build -f Dockerfile.cross --target linux-desktop -o release/ .
docker build -f Dockerfile.cross --target windows-desktop -o release/ .
```

## Implementation Steps

1. Create `Dockerfile.cross` with multi-stage build (web-builder → linux-desktop → windows-desktop → output)
2. Add `bundle-desktop-assets` step in Dockerfile (copy skills/plugins into embedded-assets)
3. Add Makefile targets: `docker-release`, `docker-desktop-linux`, `docker-desktop-windows`
4. Test each target builds successfully
5. Validate output binaries

## Validation
- `docker build` exits 0 for each target
- Output binaries exist and are non-empty
- Linux binary runs: `docker run --rm release/ocode-desktop-linux-amd64 --help` (or version check)
- Windows binary is a valid PE: `file release/ocode-desktop-windows-amd64.exe`
