# Plan: Stabilize web and desktop chat streaming

**Created:** 2026-08-05 15:32:48 +08
**Status:** Draft

## Context

The shared React app is used by both web and desktop. A session-tab refactor
left only a status-filtered SSE subscription in `SessionTabSync`, while the
old chat-event handlers were removed from `SessionPage`. The current
single-session chat store should remain focused; a per-session state map is
deferred as a separate feature.

## Goals

- Chat deltas, tools, snapshots, turn completion, questions, permissions, and
  errors render in the active tab.
- Events from concurrent sessions/projects cannot cross-contaminate UI state.
- Switching tabs/projects and reconnecting does not lose or duplicate messages.
- Existing per-project tab persistence and active-tab selection remain
  unchanged.

## Approach

Use one persistent unfiltered SSE mirror, tag server events with session IDs,
and route events to the active session's existing ChatState. Correlate the
first request from a temporary tab with `session_started` so its real ID is
available before model callbacks begin. Subscribe before loading history and
use snapshot suffix/prefix matching for deduplication. Background sessions
are recovered from durable history when activated.

## Implementation Steps

1. Add session metadata to headless/RC SSE events, correlate temporary-tab
   session creation, and route/filter broadcasts without changing unrelated
   server behavior.
2. Subscribe before loading initial session history and preserve recoverable
   snapshots on reconnect.
3. Consolidate the removed event-to-reducer mapping in `SessionTabSync`,
   including active-session guards and pagination-safe snapshot merging.
4. Add regression tests, format/typecheck, run targeted tests, then run the
   broadest practical validation.

## Risks & Considerations

- Do not overwrite unrelated uncommitted user changes.
- Avoid competing mirror subscriptions that duplicate events.
- RC bridge payloads may lack session metadata; decorate them at the server
  boundary using the bridge's single session ID.
- A browser reconnect may receive a full snapshot after live events; merging
  must be idempotent.
- Streaming state is transport/UI state, not persisted tab state.
