# Bound `orphanRecoveryWG.Wait()` in `Agent.Shutdown()` (con #4)

**Status:** Implemented and validated (2026-09-16)

## Context

`Agent.Shutdown()` (`internal/agent/agent.go`) called `a.orphanRecoveryWG.Wait()`
with **no timeout**. The tracked goroutine (`recoverOneOrphanedToolCall`) runs
`handleToolCallWithContext` under a 30s ctx, but that ctx only bounds the
*caller's* `select` — the goroutine itself runs until the underlying **tool**
returns. A tool blocked on its own I/O (`git push` on a credential prompt, a
stuck network call) therefore outlives the ctx and hangs every `Shutdown`
caller indefinitely: the TUI model switch, `/new`, server session replacement,
and idle eviction. Measured: the OLD code times the regression test out at 45s.

Companion hazard, proven empirically before fixing: `snapshot.Store.Reset()`
does **not** poison the store against later writes, so a straggler's
`RegisterWrite` landing after teardown re-seeds the process-global `fileWrites`
registry under a dead agent id, with nothing left to unregister it —
permanently failing that path's `UndoByToolCallID` with a phantom cross-agent
conflict (`PHANTOM CONFLICT: agent="agent-old" seq=2 tc="late-tc"`). The old 5s
drain masked this by letting the write land before `Reset`. So bounding the
wait alone would have *introduced* that race.

## Goals

- `Shutdown()` returns bounded even when an orphan-recovery tool is blocked.
- A straggler cannot corrupt the global write registry.
- No behavior change for live, reused stores (`SwitchSession`, global store).

## Approach

1. **`Store.Retire()`** (new, plus `Retired()`) — terminal variant of `Reset`:
   sets a sticky `retired` flag under `s.mu`, clears live state, unregisters the
   agent, and makes `RegisterWrite` a no-op thereafter.
2. **Lock order** — `RegisterWrite` now holds `s.mu` across its registry append
   so the retired check and the append are atomic vs `Retire`. Order is
   `s.mu -> fileWriteMu`, matching `UndoByToolCallID` via
   `crossAgentWriteAfterSeq`; no existing path nests the reverse.
3. **Bounded wait** — `orphanRecoveryShutdownWait` (2s) via
   `waitForOrphanRecovery`, which runs the `WaitGroup.Wait` on a crashguard
   goroutine so the bounded `select` can win (mirrors `waitForPendingSaves`).

`Retire` is deliberately a *separate method* from `Reset`: `Reset` also runs on
live stores — `SwitchSession` rebinds a rebuilt agent's store, and the
process-global store is long-lived — so a permanent flag there would silently
stop all future change tracking. `Backup` is intentionally left unguarded (an
append to a discarded store is inert; `WriteSeq` stays 0 so undo skips the
cross-agent check, and the journal row stays legitimately undoable in the
owning session).

## Implementation Steps

1. Add `retired bool` to `Store` with a comment explaining why it is distinct
   from `Reset`.
2. Restructure `RegisterWrite`: take `s.mu`, early-return when `s.retired`,
   keep the append + `WriteSeq` back-fill under the same lock.
3. Add `Retire()` and `Retired()`.
4. Add `orphanRecoveryShutdownWait = 2 * time.Second`.
5. Add `waitForOrphanRecovery(timeout)` — `WaitGroup.Wait` on a crashguard
   goroutine + bounded `select`, emitting `[ORPHAN] ...` on timeout.
6. `Shutdown()`: call `a.waitForOrphanRecovery(orphanRecoveryShutdownWait)`,
   then `a.snapshotStore.Retire()` (was `Reset()`).
7. Add the three test files.
8. Add the `CHANGES.md` entry.

## Risks & Considerations

- **Lock order**: `RegisterWrite` now nests `s.mu -> fileWriteMu`. Verified all
  `fileWriteMu` users (lines 216, 237, 262) and that none nests the reverse.
  `RegisterWrite` runs after every successful write tool, so the held-lock span
  is kept minimal (registry append + back-fill only).
- **Live-store regression**: `Reset` must stay writable. Pinned by
  `TestStoreResetDoesNotRetire` and `TestSwitchSessionResetDoesNotRetire`.
- **Guard necessity**: `TestStoreRetireRejectsLaterWrites` was verified to FAIL
  with the guard disabled, and `TestShutdownBoundsOrphanRecoveryWait` to time out
  at 45s against the old unbounded wait — both are genuine regression tests.
- **Pre-existing failures** (confirmed identical at the `pristine` worktree
  baseline `653bb55a`): 6 in `internal/agent`
  (`TestNewClientGrokSubscription`,
  `TestScheduleDAGPredecessorContextTruncation`,
  `TestTruncateToolResultByLines`, `TestTruncateToolResultByChars`,
  `TestCleanupToolResults`,
  `TestTruncateToolResultCharCapHintsActualCutLine`), the `internal/server`
  `TestTerminalWS*`/`TestTerminalKillEndpoint` set (`posix_openpt: operation not
  permitted` in this sandbox), and the `internal/snapshot` journal-gc/`TempDir`
  `-race` flake.
