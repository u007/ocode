# Plan: Complete terminal history persistence and restore

**Created:** 2026-09-08 11:33:54 +08
**Status:** Complete (validation recorded below)

## Context

The partial terminal history work persists PTY chunks to disk but only reads through a live in-memory file. The registered history route has no Server shim, so the Go package does not compile. The frontend still treats bounded localStorage scrollback as the primary restore source and can display a rendering-drop marker.

## Goals

- Persist the complete PTY byte stream for named terminals and read it after session exit or server restart.
- Expose authenticated, project-scoped, bounded history pages with strict offsets and base64 data.
- Restore server history sequentially before attaching the WebSocket, then bridge the REST snapshot to live output without gaps or duplicates.
- Keep localStorage as an explicit fallback for old/missing history endpoints and preserve existing terminal/WebSocket behavior.
- Add focused Go and TypeScript tests without touching unrelated working-tree changes.

## Approach

Use a collision-resistant filename derived from the authorized project and terminal ID. Keep live writes under the session history mutex; reopen read-only descriptors for HTTP range snapshots so restart reads do not depend on a live session. Resolve and validate local/remote project identity in the history handler, and reject active-session project mismatches.

The history API uses `offset`/`limit` and returns `{id, offset, next_offset, snapshot_end, eof, data, state}`. The frontend fetches pages oldest-to-newest, validates exact byte progression and base64, sets xterm scrollback before writing, and connects with `history_offset=snapshot_end`. A resumed live session replays only bytes after that cursor while the old no-cursor attach path remains unchanged.

## Risks & Considerations

- A REST snapshot must be bridged to the live socket under the session mutex; otherwise output can be duplicated or missed.
- PTY data is raw bytes, so JSON must use base64 and frontend decoding must preserve UTF-8 sequences across pages.
- xterm's configured scrollback can silently evict restored lines; increase it from the snapshot byte upper bound before replaying server pages.
- LocalStorage is bounded and cannot be used as a silent fallback for non-404 server failures.
- The project has many unrelated working-tree edits; only the listed terminal history files should be changed.
