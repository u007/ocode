# Plan: Implement cross-process shared LSP broker

## Goal

Share one compatible `gopls` process across TUI, desktop/web, and nested CLI processes using a cross-platform loopback TCP broker, while preserving local fallback for incompatible or unsupported cases.

## Constraints

- Do not modify unrelated user working-tree changes.
- Keep `internal/lsp.Manager` and existing local stdio behavior compatible.
- Broker binds only to `127.0.0.1`.
- No duplicate LSP spawn for transient connection failures.
- V1 supports multiple compatible clients; conflicting document state uses isolated local mode.
- Start with `gopls`; other language servers remain local until adapters are validated.

## Implementation phases

0. **Pre-implementation discovery**
   - Inspect config, paths, file-lock, process cleanup, and existing LSP lifecycle APIs.
   - Resolve the open decisions below against current code before adding broker code.

1. **Configuration and identity primitives**
   - Locate config schema and global data/file-lock helpers.
   - Add `lsp_shared` default-enabled setting and precedence.
   - Implement canonical root normalization and stable server identity including resolved executable fingerprint/version, args, language ID, workspace/configuration inputs.
   - Add broker UUID/epoch, metadata schema, atomic write/compare-delete, and per-identity startup lock.

2. **Transport and broker lifecycle**
   - Add length-prefixed, bounded JSON framing with protocol version and envelope kinds.
   - Implement loopback TCP listener, authenticated handshake, accept loop, bounded queues, deadlines, and idempotent shutdown.
   - Launch the existing stdio LSP client in the broker, publish metadata only after upstream initialization, and clean up child processes with graceful close, force kill timeout, and `Wait`.
   - Implement discovery, election, stale metadata handling, and retry with jitter.

3. **Compatible multi-client protocol**
   - Define client registration and initialization compatibility checks.
   - Implement bidirectional request-ID rewriting, pending maps, cancellation, deadlines, and response routing.
   - Define server notification matrix and reject unsupported traffic explicitly.
   - Route server-originated requests only to a designated compatible owner; reject when no owner exists.

4. **Canonical document and diagnostic state**
   - Implement URI normalization and reference-counted canonical documents.
   - Accept first compatible open; reject divergent open/change state with an explicit isolated-mode result.
   - Serialize accepted changes, assign broker versions, replay compatible state on reconnect, and close upstream documents after the final client closes.
   - Route diagnostics by URI, canonical version, subscriber, and broker generation; propagate clears and ignore stale generations.

5. **Manager integration and fallback**
   - Add broker-backed client transport behind the existing manager/client abstraction.
   - Attempt broker connection before local spawn for supported servers.
   - Distinguish absent/dead broker, transient transport errors, incompatibility, and explicit sharing disablement.
   - Ensure only confirmed-dead or explicitly isolated paths create local servers.
   - Ensure Manager close releases client connection without killing a shared broker that still has clients.

6. **Tests and validation**
   - Unit-test identity, metadata, locks, framing, authentication, request IDs, queue bounds, document versions, diagnostics, and lifecycle.
   - Integration-test two compatible clients with a fake LSP server, conflicting documents, server-originated requests, reconnects, stale metadata, concurrent election, idle shutdown, and split-brain prevention.
   - Add real `gopls` integration coverage when installed.
   - Run `gofmt`, targeted `go test ./internal/lsp/...`, full `go test ./...`, `go vet ./...`, and relevant builds.
   - Validate macOS/Linux/Windows-specific path, metadata, loopback, and process cleanup behavior where CI permits.

## Implementation Steps

1. Read current config/path/lock/LSP lifecycle APIs and record exact integration points.
2. Implement broker metadata, identity, and transport with fake-server tests before Manager integration.
3. Add compatibility/document routing and fallback semantics behind the existing Manager interface.
4. Run targeted tests, then full validation and platform builds.

## Open implementation decisions to resolve before coding

- Exact config field location/name and existing config merge precedence.
- Whether the broker protocol lives in `internal/lsp/broker` or a smaller package split between transport and lifecycle.
- Exact V1 supported LSP message matrix for `gopls`, based on current `internal/lsp/client.go` behavior.
- Isolated local-server identity and observability when a client is incompatible.
- Idle grace period, maximum clients, frame size, queue limits, and request deadlines.
