# Fix: desktop/web UI hangs after approve/cancel permission request

## Root Cause Analysis

The hang occurs in **headless server mode** (desktop app and `ocode serve` without TUI) when the agent's `Step()` encounters a **second permission ask** during the resolution of a first permission.

### Flow

1. Permission ask arrives → web `PermissionDialog` shows
2. User clicks Approve → `POST /api/permissions/resolve`
3. Server calls `as.agent.Step(working)` **synchronously** (blocking HTTP handler)
4. During `Step()`, the agent encounters a **second** permission ask
5. `Step()` returns early (pauseAfterResults)
6. **During `Step()`**, `wireHeadlessAgentCallbacks` → `OnMessage` fires → broadcasts `permission` SSE for the **second** ask → browser sets `pendingPermission` → dialog shows
7. **After `Step()` returns**, server broadcasts `permission_resolved` for the **first** ask
8. Browser receives `permission_resolved` → `PERMISSION_RESOLVED` reducer **unconditionally** clears `pendingPermission: null` → **closes the dialog for the second permission**
9. Agent is waiting for second permission → web UI shows no dialog → **UI appears hung**

### The Race

```
SSE events in order:
  1. permission (2nd ask)    → pendingPermission = {2nd ask}
  2. permission_resolved     → pendingPermission = null  ← WRONG: closes 2nd ask's dialog
  3. messages                → updates transcript (includes 2nd ask)
  4. turn_done               → stops streaming
```

### Same issue in TUI bridge mode

When `/rc` is active and the web resolves a permission:
- TUI broadcasts `permission_resolved` to web (after processing the first resolution)
- If the next agent `Step()` produces a second permission ask, its `permission` event arrives via mirror SSE
- The `permission_resolved` from the first resolution can arrive after the second's `permission` event, clearing the 2nd dialog

## Fix

Make `PERMISSION_RESOLVED` carry the `request_id` so the reducer only clears the matching permission, not any pending permission.

### Files to modify

1. **`web/src/stores/chatStore.tsx`**
   - Add `requestId?: string` to `PERMISSION_RESOLVED` action type
   - Reducer: only clear `pendingPermission` when `requestId` matches (or when `requestId` is absent for backward compat)

2. **`web/src/components/Layout/SessionTabSync.tsx`**
   - Extract `request_id` from the `permission_resolved` SSE event data
   - Pass it as `requestId` in the `PERMISSION_RESOLVED` dispatch

3. **`web/src/hooks/useChat.ts`**
   - Pass `requestId` in the `dispatch({ type: "PERMISSION_RESOLVED", ... })` call

### Reducer logic

```typescript
case "PERMISSION_RESOLVED":
  return updateSession(state, action.sessionId, (s) => {
    // If a specific requestId is provided, only clear if it matches
    if (action.requestId && s.pendingPermission && s.pendingPermission.request_id !== action.requestId) {
      return s;
    }
    return { ...s, pendingPermission: null };
  });
```

### Dispatch in SessionTabSync

```typescript
case "permission_resolved": {
  const evData = data as { request_id?: string };
  chatDispatch({ type: "PERMISSION_RESOLVED", sessionId, requestId: evData.request_id });
  break;
}
```

### Dispatch in useChat resolvePermission

```typescript
dispatch({ type: "PERMISSION_RESOLVED", sessionId, requestId });
```

## Implementation Steps

2. Update `SessionTabSync.tsx` — extract `request_id` from SSE event data and pass to dispatch
3. Update `useChat.ts` — pass `requestId` in the PERMISSION_RESOLVED dispatch
