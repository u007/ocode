- id: vbnet-syntax-01
  answer: |
    Declare a variable with `Dim`, optionally with `As` for the type: `Dim x As Integer`. Statements are terminated implicitly at the end of a line (no semicolon needed). Multiple statements can be placed on one line separated by colons. To continue one statement across multiple lines, end the line with an underscore `_` (the line continuation character).

- id: vbnet-syntax-02
  answer: |
    `Option Strict` controls implicit type conversion rules — when `On`, it disallows implicit narrowing conversions and late binding, forcing explicit casts. `Option Explicit` requires all variables to be declared before use. `Option Infer` enables local type inference so `Dim x = 5` infers x as Integer. `Option Strict On` matters because it catches potential runtime errors (like overflow or type mismatch) at compile time, making code safer and more predictable.

- id: vbnet-syntax-03
  answer: |
    A `Module` cannot be instantiated; its members are implicitly `Shared` (static). It cannot be inherited and cannot be used as a type for an object variable. A `Class` can be instantiated, supports inheritance (Inherits), can implement interfaces, and can have both instance and shared members. Classes are the primary building block for object-oriented design in VB.NET.

- id: vbnet-syntax-04
  answer: |
    A `Sub` performs an action and does not return a value. A `Function` performs an action and returns a value of a specified type, declared in its signature (e.g., `Function Add(a As Integer, b As Integer) As Integer`). A Function returns a value using the `Return` statement.

- id: vbnet-props-01
  answer: |
    An auto-implemented property is declared without explicit getter/setter bodies — the compiler generates the backing field and accessors automatically: `Public Property Name As String`. A full property declares an explicit backing field and custom Get/Set blocks: `Private _name As String` / `Public Property Name As String` with `Get` / `Set` bodies. The auto-implemented form is simpler but doesn't allow custom logic in accessors.

- id: vbnet-props-02
  answer: |
    The backing field name is auto-generated by the compiler and not directly accessible by a predictable name. Initialize an auto-property with a default value by assigning at declaration: `Public Property Name As String = "default"`.

- id: vbnet-props-03
  answer: |
    Declare a read-only property with only a `Get` accessor: `Public ReadOnly Property Count As Integer`. Declare a write-only property with only a `Set` accessor: `Public WriteOnly Property Value As String`. Yes, an auto-implemented property can be `ReadOnly` (or `WriteOnly`): `Public ReadOnly Property Id As Integer`.

- id: vbnet-props-04
  answer: |
    A default property (also called an indexer) can be accessed without specifying the property name, e.g., `Dim x = obj(0)`. The constraint is that a default property must be parameterized — it must take at least one argument (typically an index or key). This is what distinguishes it from a normal property.

- id: vbnet-null-01
  answer: |
    In VB.NET, `Nothing` represents the default value of a type. For a reference type, it means the variable holds no object reference (equivalent to `null` in C#). For a value type, it represents the default-constructed value (e.g., 0 for Integer, False for Boolean, a DateTime of 0001-01-01). `Nothing` is essentially `default(T)` in .NET terms.

- id: vbnet-null-02
  answer: |
    Declare a nullable value type with the `?` suffix: `Dim x As Integer?`. Check if it has a value with `If x.HasValue Then`. Read its value safely with `x.Value` (throws if no value). You can also use the null-coalescing `If` operator: `If(x, defaultValue)` to get the value or a default.

- id: vbnet-null-03
  answer: |
    `If(a, b)` is a two-argument null-coalescing operator — it returns `a` if `a` is not Nothing, otherwise `b`. It is a true operator with short-circuit evaluation and type inference. `IIf(a, b, c)` is a legacy function that evaluates all three arguments before returning (no short-circuiting) and returns `Object`. `If` is preferred because it short-circuits (only evaluates the needed branch), infers the result type, and avoids the overhead and ambiguity of the old `IIf` function.

- id: vbnet-null-04
  answer: |
    `Is Nothing` / `IsNot Nothing` performs a direct reference comparison (or null check for nullable value types), which is unambiguous and always correct. `= Nothing` invokes the overloaded equality operator (`=`) which could have unexpected behavior if the type overloads `=`. `Is` is more explicit about intent and avoids relying on operator overloads.

- id: vbnet-errors-01
  answer: |
    Structure: `Try` block contains code that may throw an exception. One or more `Catch ex As ExceptionType` blocks handle specific exceptions. An optional `Finally` block runs regardless of whether an exception occurred — it always executes after the Try block (or after a matching Catch block), used for cleanup like closing files or releasing resources.

- id: vbnet-errors-02
  answer: |
    `Catch ex As Exception When condition` adds a filter predicate to a Catch block — the handler only runs when the condition evaluates to True. This is preferred over catching the exception and re-checking inside the block because it keeps the code cleaner and allows the exception to fall through to other Catch blocks (or become unhandled) if the condition is false, rather than being caught and then ignored.

- id: vbnet-errors-03
  answer: |
    `Throw` (with no argument) rethrows the current exception and preserves the original stack trace. `Throw ex` throws the exception object but resets the stack trace to the current location, losing the original call stack information. Using bare `Throw` is preferred when rethrowing because it preserves debugging information.

- id: vbnet-errors-04
  answer: |
    `On Error Goto Label` is the legacy unstructured error handling from VB6, where control jumps to a labeled line and the `Err` object holds error details. Structured `Try/Catch` is preferred because it provides a `Finally` block for guaranteed cleanup, supports multiple typed catch blocks, doesn't use unstructured jumps, integrates properly with the .NET exception hierarchy, and is the idiomatic approach in modern .NET.

- id: vbnet-linq-01
  answer: |
    ```vb
    Dim results = From item In collection
                  Where item.Age > 18
                  Select item.Name
    ```
    Keywords: `From` (source), `Where` (filter), `Select` (projection). The query starts with `From`, optionally includes `Where`, and ends with `Select` to project the output.

- id: vbnet-linq-02
  answer: |
    ```vb
    Dim grouped = From item In collection
                  Group By category = item.Category Into Group
                  Select category, Count = Group.Count()
    ```
    The `Group By ... Into` syntax groups elements by a key, and the `Group` keyword gives access to the aggregated elements in each group, allowing aggregates like `Count()`, `Sum()`, `Average()`, etc.

- id: vbnet-linq-03
  answer: |
    `Aggregate` performs a cumulative operation over a sequence — it applies an accumulator function across all elements (similar to a fold/reduce). For example: `Aggregate Function(acc, item) acc + item.Value`. `From` is the query starter that defines the source collection. `Aggregate` is an operator applied after `From` to combine elements into a single result.

- id: vbnet-linq-04
  answer: |
    Deferred (lazy) execution means the LINQ query is not executed when defined — it is only executed when the result is iterated (e.g., in a `For Each` loop) or when a materialization method is called. To force immediate execution in VB, use methods like `.ToList()`, `.ToArray()`, `.Count()`, `.First()`, `.Single()`, `.Sum()`, or `.Aggregate()`.

- id: vbnet-events-01
  answer: |
    Declare a field with `WithEvents`: `Private WithEvents btn As Button`. Declare a handler method with `Handles`: `Private Sub btn_Click(sender As Object, e As EventArgs) Handles btn.Click`. The compiler wires the handler to the event automatically — no explicit `AddHandler` call is needed. One `Handles` clause can bind to multiple events with comma-separated lists: `Handles btn1.Click, btn2.Click`.

- id: vbnet-events-02
  answer: |
    `AddHandler` dynamically associates a delegate (method) with an event at runtime. `RemoveHandler` removes that association. `AddressOf` creates a delegate from a method name. You must use them instead of `Handles` when: (1) handling `Shared` events, which cannot be handled through `WithEvents`/`Handles`; and (2) handling events raised by a `Structure`, since a Structure cannot declare a `WithEvents` field. They are also used for dynamic subscription/unsubscription at runtime.

- id: vbnet-events-03
  answer: |
    Declare a custom event: `Public Event MyEvent(sender As Object, e As EventArgs)`. Raise it: `RaiseEvent MyEvent(Me, args)`. Handlers receive the same arguments — the sender and the event args object. The event can also be declared with a custom delegate type or with `EventHandler`/`EventHandler(Of T)`.

- id: vbnet-events-04
  answer: |
    Choose `WithEvents`/`Handles` for static wiring — simpler syntax, designer-generated code, compile-time checking. Choose `AddHandler`/`RemoveHandler` for: dynamic wiring at runtime (subscribe/unsubscribe), handling `Shared` events, handling events from `Structure` types, and managing event subscriptions programmatically where the target isn't known at design time.

- id: vbnet-oop-01
  answer: |
    `Inherits` establishes that a class derives from a base class — a class can inherit from exactly one base class (single inheritance). `Implements` establishes that a class implements an interface — a class can implement multiple interfaces. `Inherits` provides implementation reuse; `Implements` provides contract adherence.

- id: vbnet-oop-02
  answer: |
    `Overridable` — a base class member that derived classes can override. `Overrides` — a derived class member that overrides an `Overridable` or `MustOverride` base member. `MustOverride` — an abstract member that derived classes must override (the class must also be `MustInherit`). `MustInherit` — an abstract class that cannot be instantiated directly. `NotOverridable` — a member that derived classes cannot override (sealed).

- id: vbnet-oop-03
  answer: |
    `Shared` means the member belongs to the type itself rather than to any instance. A shared member is accessed via `ClassName.MemberName` (e.g., `Math.PI`), not through an instance variable. Only one copy exists across all instances. Instance members are accessed through an object reference: `obj.MemberName`.

- id: vbnet-oop-04
  answer: |
    `Me` — refers to the current instance of the class. `MyBase` — refers to the immediate base class instance, used to call base class members that are overridden. `MyClass` — refers to the current class's implementation regardless of inheritance, using non-virtual dispatch. `MyClass` differs from `Me` when a derived class overrides a method — `MyClass` always calls the current class's version (non-polymorphic dispatch), while `Me` would call the most-derived override.

- id: vbnet-convarr-01
  answer: |
    `CType` — general-purpose conversion that handles widening and narrowing conversions, as well as user-defined conversions. Use it when no inheritance relationship exists. `DirectCast` — fast cast that only works when there is an inheritance relationship between types; no conversion is performed. Use it when you know the exact type. `TryCast` — like `DirectCast` but returns `Nothing` instead of throwing an exception on failure; only works with reference types.

- id: vbnet-convarr-02
  answer: |
    Widening conversion: converting to a type that can represent all values of the source type without data loss (e.g., `Integer` to `Long`). Narrowing conversion: converting to a type that might lose data or overflow (e.g., `Long` to `Integer`). With `Option Strict On`, widening conversions are allowed implicitly, but narrowing conversions require an explicit cast (e.g., `CType`, `DirectCast`, `CInt`).

- id: vbnet-convarr-03
  answer: |
    Yes, VB.NET arrays are 0-based. Resize an array while preserving contents with `ReDim Preserve arr(newUpperBound)`. In `Dim a(n)`, `n` is the upper bound, so the array has `n+1` elements indexed from 0 to `n`.

- id: vbnet-convarr-04
  answer: |
    `CInt`, `CStr`, `CDbl` etc. are legacy conversion functions that convert a value to Integer, String, Double, and so on. Use `&` (ampersand) for string concatenation instead of `+` because `+` can perform either addition or concatenation depending on the operand types, leading to ambiguity and potential runtime errors. `&` always performs string concatenation and is unambiguous.
