# Excel preview and Save: Univer sheet over ExcelJS and SheetJS

## Summary

`ExcelViewer` (`web/src/components/Preview/ExcelViewer.tsx`) shows a spreadsheet in an open-source Univer sheet (`@univerjs/presets`, `@univerjs/preset-sheets-core` and `@univerjs/core`, all `^1.1.0`, see `web/package.json`). Univer's xlsx importer is a Pro feature, so ocode converts the workbook itself into Univer's `IWorkbookData` and never gives Univer a file. Floating images (drawings) are extracted by the converter and painted by a read-only overlay, because Univer's OSS grid does not render them (see Floating images and the image overlay). An uncontrolled `.xlsx` with no capped sheet is editable and can be saved back; Save patches the original package by diffing the live grid against a load-time baseline, so drawings, media, styles and shared strings stay byte-identical (see Editing and Save). Every other kind is read-only.

## Pipeline by input

| Input | Parser | Converter |
| --- | --- | --- |
| `.xlsx` (and `.xlsm`, see Known gaps) | ExcelJS `wb.xlsx.load`, dynamically imported so it stays out of the main bundle (`univerData.ts:558-562`), after `prefixDrawingNamespaces` (`univerData.ts:525`, see Default-namespace drawings) | `workbookFromExcelJs` (`univerData.ts:332`) |
| `.csv`, `.tsv` | SheetJS on the UTF-8 decoded text (`univerData.ts:554-556`) | `workbookFromSheetJs(wb, true)` (`univerData.ts:442`), first row styled as a header |
| `.xls` | SheetJS, `type: "array"` (`univerData.ts:565`) | `workbookFromSheetJs(wb, false)` |
| split-view `content` (controlled mode) | SheetJS on the live string, via `workbookFromDelimitedText` (`univerData.ts:511`, called from `ExcelViewer.tsx:301`) | `workbookFromSheetJs(wb, true)` |

The file rows are parsed by `workbookFromFileBytes` (`univerData.ts:548`). `ExcelViewer` calls it (`ExcelViewer.tsx:316`), and so does the print document (`preview-print-save-as-pdf.md`), so both show the same cells on disk. Print reads the saved file, not the live grid, so unsaved edits do not appear in print.

Delimited text is decoded as UTF-8 before SheetJS reads it. Raw bytes would be read as latin-1 and garble every non-ASCII cell. The bytes come from `apiClient.fetchFileRaw` (`ExcelViewer.tsx:312`). The server allowlists `.xlsx`, `.xlsm`, `.xls` and `.csv` in `previewRawTypes` (`internal/server/handler_files.go:1224`, entries at `:1228-1231`).

### Floating image extraction

`workbookFromExcelJs` (`univerData.ts:332`) extracts drawings into `ConvertedWorkbook.images[]` (`univerData.ts:81-87`). Each `WorkbookImage` (`univerData.ts:89-101`) is `{sheetId, sheetName, dataUrl, fromCol, fromRow, toCol, toRow, extWidth, extHeight}`; the anchor is the image's top-left cell as fractional column/row coordinates, plus either the two-cell end (`toCol`/`toRow`, ExcelJS `range.br`) or a one-cell extent in px (`extWidth`/`extHeight`, ExcelJS `range.ext`). Each pair is both set or both null (`anchorPair`, `univerData.ts:104-108`). `extWidth`/`extHeight` start as ExcelJS's loose `range.ext` guess but are replaced with the picture's true size from the drawing XML for OOXML files (see below).

The extractor uses ExcelJS's loosely-typed `Worksheet.getImages()` (`univerData.ts:353`) and `Workbook.getImage()` (`:361`). Shape/result failures are logged and skipped, never swallowed (`:338-365`). A per-image cap of 4 MiB (`MAX_IMAGE_BYTES`, `univerData.ts:344`) skips larger images with a warning (`:376-378`), and unsupported extensions (EMF/WMF and anything other than jpg/jpeg/png/gif) are logged and skipped (`:380-385`). The surviving buffer or base64 becomes a `data:` URL (`:386-409`) and the anchor comes from `img.range.tl` (`:403-411`).

**True size from EMU extents.** ExcelJS `getImages()` exposes only cell anchors — a bounding box, not the picture's real size — so stretching to that range distorts the image. `extractDrawingExtents(buf)` (`univerData.ts:550`, exported) reads `<a:ext cx cy>` EMU values from `xl/drawings/*.xml` (`OOXML_DRAWING_PART`, `univerData.ts:517`) with JSZip + `DOMParser`, skips `<a:ext uri="creationId">` nodes (they carry no finite `cx`/`cy`), converts EMU→px at 96 dpi (`EMU/9525`, since 914400 EMU = 1 inch, `univerData.ts:567`), and returns extents in picture order with `null` where none was found. `workbookFromFileBytes` (`univerData.ts:582`) calls it after conversion and writes each extent into `WorkbookImage.extWidth`/`extHeight` (`:599-606`), replacing the loose cell-range guess. Verified on the real `09nov-leave.xlsx`: logo 147.94x119.58px, signature 160x110.56px.

### Default-namespace drawings

Some writers emit `xl/drawings/drawingN.xml` with `<wsDr xmlns="...spreadsheetDrawing">` and no `xdr:` prefix. ExcelJS 4.4 matches tag names literally, parses such a drawing to `undefined`, and `wb.xlsx.load` throws `Cannot read properties of undefined (reading 'anchors')`, so the viewer showed `Spreadsheet failed`. `prefixDrawingNamespaces` (`univerData.ts:525`, exported) rewrites those parts to the prefixed form with JSZip (dynamically imported) before ExcelJS loads (`univerData.ts:562`). It returns the original buffer untouched when no part needs rewriting (`univerData.ts:539`). The save path never sees the rewritten copy: `ExcelViewer` keeps the ORIGINAL bytes (`baseBytesRef`, `ExcelViewer.tsx:314`), and `patchWorkbookBytes` patches those.

## Runtime (`univerMount.ts`)

- `mountUniverSheet` (`univerMount.ts:84`) is loaded with a dynamic import (`ExcelViewer.tsx:336-338`), so Univer is a lazy chunk. `PreviewSurface` lazy-loads `ExcelViewer` too (`PreviewSurface.tsx:22`).
- Chrome is off: header, toolbar, formula bar, footer and context menu (`univerMount.ts:102-110`). The workbook is editable only when the viewer asks for it: `editable = opts?.editable === true` (`univerMount.ts:114`) and `workbook.setEditable(editable)` (`univerMount.ts:118`), where the flag comes from the viewer's mount effect (`ExcelViewer.tsx:334-335`, passed at `:339`).
- Dark mode follows the editor appearance (`ExcelViewer.tsx:110-116`, passed to the mount at `:338` and into `createUniver` at `univerMount.ts:100`; the live toggle is the effect at `:383-386`).
- One Univer instance per converted workbook. A late mount that resolves after cancellation is disposed (`ExcelViewer.tsx:326-381`, the dispose at `:343-347`). **Deps invariant.** The mount effect depends on `[book]` only (`ExcelViewer.tsx:381`); never add `path` or `content`. A `path` change reaches it through the new `book`. Listing `path` disposed the grid in the same commit in which the activate-sheet effect (`ExcelViewer.tsx:388-397`) still held the old handle, and the viewer failed with `Spreadsheet failed: Univer has no sheet "sheet-1"`. `content` is left out for the reason at `ExcelViewer.tsx:375-377`: the effect would fire with the stale book first and double-dispose the previous grid. Regression test: `ExcelViewer.test.tsx`, "re-mounts a new .xlsx path on the same instance without a failure state".
- The sheet tab bar is ocode's own `role="tablist"` (`ExcelViewer.tsx:411`). `activateSheet` throws when Univer has no such sheet (`univerMount.ts:124-129`, the throw at `:126`).
- `activateRange` (`univerMount.ts:130-138`) resolves the A1 address and checks it before any sheet switch, so a bad address leaves the view alone. Univer does not throw on malformed A1; it returns NaN coordinates. `assertRangeInSheet` (`univerMount.ts:251-270`) therefore requires integer row, column, height and width, a height and width of at least 1, and a rectangle inside `getMaxRows()` and `getMaxColumns()`. Anything else throws `invalid range: <a1>`. Whole-column addresses such as `A:A` are not verified in a real browser.
- The handle's interface (`univerMount.ts:51-76`) is `activateSheet`, `activateRange`, `sheetNames`, `activeSheetName`, `selection`, `onSelectionChange`, `viewport`, `setDarkMode`, `snapshot` and `dispose`. The old `rebase` member is gone.
- **Viewport for the overlay.** `UniverSheetHandle.viewport()` (`univerMount.ts:69-70`, implementation `:175-232`) exposes `metrics()` (`:177-210`) — live scroll x/y, zoom, row/column header sizes and cumulative per-row/per-column pixel offsets — and `subscribe(cb)` (`:211-230`) on Univer's `Scroll`, `SheetZoomChanged` and `ActiveSheetChanged` events (`:215-217`). `dispose()` ends the viewport subscriptions (`:240`).

## Floating images and the image overlay

- `SheetImageOverlay` (`web/src/components/Preview/SheetImageOverlay.tsx`) is a read-only layer that paints the extracted images at their cell anchors. It is a sibling of the Univer container in the viewer (`ExcelViewer.tsx:460-466`) and is `pointer-events-none`, `aria-hidden` and clipped (`SheetImageOverlay.tsx:109`), so the grid keeps every pointer event.
- **Size.** `imageSizePx` (`SheetImageOverlay.tsx:30-43`) PREFERS the drawing's EMU extent: `extWidth`/`extHeight` (populated from the `<a:ext cx cy>` values by `extractDrawingExtents`) win first, scaled by the live sheet zoom (`:33-35`). Only when those are null does it fall back to the two-cell `br` extent (`toCol`/`toRow`, measured through the grid's own column and row positions, `colPos`/`rowPos` at `:18-27`, branch at `:36-41`), then to `DEFAULT_IMAGE_PX` (180x120, `SheetImageOverlay.tsx:15`, fallback at `:42`) as a last resort. The two-cell anchor is a bounding box, not the picture's real size, so using it as the size stretches/distorts the image (the old behaviour: 108x134 drawn for an Excel 148x120 image). Verified on the real `09nov-leave.xlsx`: logo 147.94x119.58px, signature 160x110.56px. Its top-left position combines the fractional anchor and the viewport's scroll/offset metrics (`:90-91`). The box is not clamped to the layer edge (`:95`): the layer is `overflow-hidden`, and clamping squashed images.
- Off-screen images are culled by testing the placed box against the measured layer size (`:93-94`). A `ResizeObserver` plus the viewport subscription coalesce a burst of Univer events into one `requestAnimationFrame` repaint (`:54-80`). A regression test with the real signature from `09nov-leave.xlsx` (rows ~66.27–73) proves an off-screen image renders in-grid once the viewport scrolls to row 60; that fixture carries no EMU extent, so it is sized from its two-cell fallback extent (`SheetImageOverlay.test.tsx:202-226`).
- A thumbnail side panel remains as a fallback (`ExcelViewer.tsx:469-493`); clicking a thumbnail opens a Radix `Dialog` lightbox (`:494-499`, import at `:19`). The panel is titled `Images in this workbook (shown here; the grid overlay is view-only)` (`:471-473`).
- **Stacking invariant.** Univer's canvases are `position:absolute; z-index:8`. The Univer container (the `containerRef` div, `ExcelViewer.tsx:459`) must stay an isolated stacking context, which the Tailwind class `isolate` (`ExcelViewer.tsx:458-459`) provides. Without it the canvases paint over this overlay and no image is visible on the grid. Keep `isolate` on that element.
- **Browser verify.** The overlay is `pointer-events-none`, so `elementFromPoint` never returns it. Check the `.pointer-events-none img` bounding boxes and a screenshot instead. An image anchored right of a narrow preview pane is culled, so widen the pane ("Focus preview (reader mode)") before concluding that an image is missing.

## Limits

- File size: refused before any parser runs at 15 MiB (`MAX_FILE_BYTES`, `univerData.ts:47`; `assertWithinFileLimit`, `univerData.ts:111-116`). ExcelJS and SheetJS both hold the whole file, which is why the check comes first (`univerData.ts:549-550`).
- Per sheet: 50000 rows (`MAX_ROWS`, `univerData.ts:49`) and 200 columns (`MAX_COLS`, `univerData.ts:51`). SheetJS is asked for one row past the cap (`SHEETJS_READ_ROWS`, `univerData.ts:56`) so a longer sheet is detected.
- Truncation is visible. The tab bar says `Showing first 50000 rows … large sheet truncated` (`ExcelViewer.tsx:450-452`). Nothing is cut silently. A capped sheet also makes the workbook read-only (see Editing and Save).
- Overlay images are view-only: they cannot be selected or moved, their size comes from the drawing's EMU extent (falling back to the two-cell anchor, then a 180x120 estimate only when neither is present), and they do not follow row insert/delete — those edits force a values-only save instead (see Editing and Save).

## Failure behaviour

- Loud by design. A cell conversion error is rethrown with the sheet name and address (`atCell`, `univerData.ts:156-162`). The viewer shows `Spreadsheet failed: …` (`ExcelViewer.tsx:400`) and logs through `console.error` with an `ExcelViewer:` prefix.
- Image extraction errors are logged and the image is skipped, not fatal (see Floating image extraction).
- Theme: a workbook with no theme part uses the Office 2013+ default palette (`parseThemePalette` and `DEFAULT_THEME_PALETTE`, `xlsxStyle.ts:81-82` and `:40`). This is the approved fallback: the user approved it on 2026-11-03 because it matches Excel (see the comment at `xlsxStyle.ts:79`). A theme part that is present but malformed throws.
- Colours: an unresolvable colour throws (`resolveColor`, `xlsxStyle.ts:118`), and the error names the cell. Automatic colour is black for text on a filled cell and for borders with no colour (`AUTOMATIC_BLACK`, `xlsxStyle.ts:71`, used at `:222` and `:254`). This is Excel's own rule, not a fallback.
- Dates: `excelSerial` (`xlsxStyle.ts:297`) is the exact inverse of ExcelJS's read conversion, in the workbook's own date system (1900 or 1904; `DATE_1904_OFFSET_DAYS` at `xlsxStyle.ts:284`, flag read at `univerData.ts:335`). The Lotus 1900 leap-day bug is deliberately not corrected. ExcelJS does not correct it on read, so correcting it here would move early-1900 dates one serial away from the file.

## ExcelJS internals this viewer reads

Three loosely-typed ExcelJS accessors are read, validated, and throw on a shape change. None falls back silently.

- `ws._merges` (`mergeBoundsOf`, `univerData.ts:230-239`): ExcelJS has no public list of merged ranges.
- `wb._themes.theme1` (`themeXmlOf`, `univerData.ts:242-249`): the theme XML that resolves theme colours.
- `Worksheet.getImages()` / `Workbook.getImage()` (`univerData.ts:338-418`): the drawing records and payloads. Unlike the two private properties, failures here are logged and the image is skipped.

Check all three when bumping `exceljs` (`^4.4.0` in `web/package.json`).

## Editing and Save

- **Editable gate.** Editable only when all three hold: uncontrolled (`content` undefined), the path ends in `.xlsx` (case-insensitive), and no sheet is capped (`ExcelViewer.tsx:143-144`). `.xlsm`, CSV/TSV, legacy `.xls` and capped sheets stay read-only. While clean and editable, the bar shows `Editable — edits are saved when you click Save` (`ExcelViewer.tsx:453-455`).
- **What counts as an edit.** Univer runs mutations of its own while mounting, and a dirty flag set by those would show Save on an untouched file. `watchUserEdits` (`univerMount.ts:289-313`) counts a mutation only when the grid has reached `LifecycleStages.Rendered` (`:294`), the mutation runs inside a COMMAND (`commandDepth`, incremented at `:301`, decremented at `:305`), and it is not flagged onlyLocal, fromCollab, fromChangeset or syncOnly (`:309`). Each counted edit calls `onDirty`, which bumps `revision` (`ExcelViewer.tsx:340`). `dirty` is `revision > savedRevision` (`:146`). The Save button shows only when editable and dirty (`ExcelViewer.tsx:429-439`).
- **Save path.** `save` (`ExcelViewer.tsx:154-213`) takes `host.snapshot()` (`:170`) and, by default, calls `patchWorkbookBytes(baseBytesRef.current, baselineRef.current, snapshot)` (`ExcelViewer.tsx:175-177`; implementation in `xlsxPackagePatch.ts:601-682`). This is a JSZip package patcher: it opens the ORIGINAL xlsx and rewrites only the worksheet cells that differ between the load-time baseline snapshot and the live snapshot. Drawings, media, relationships, styles, shared strings and theme are carried through byte-identically (header comment at `xlsxPackagePatch.ts:15-23`). The baseline is captured when the file is opened (`baselineRef`, `ExcelViewer.tsx:284-285`, reset on load at `:279`) and advanced to the saved snapshot after each save (`:186`). On a formula edit the patcher drops `xl/calcChain.xml` and its references and sets `fullCalcOnLoad` (`xlsxPackagePatch.ts:648-674`). The bytes are then PUT through `apiClient.saveFileRaw` (`ExcelViewer.tsx:179-183`), with `expected_hash` from `baseHashRef.current` (`:181`, set from the loaded bytes at `:315`, moved to the written bytes at `:184`) and `savedRevision` captured at save start (`:190`). An edit made during the save therefore stays dirty.
- **Structural guard and values-only fallback.** `checkNoStructuralChange` (`xlsxPackagePatch.ts:210-252`) throws `Structural change detected: …` when the sheet list/order, a sheet's `rowCount`, `columnCount` or `mergeData` differ between baseline and live. The viewer recognises that error text (`ExcelViewer.tsx:197-199`) and reveals an explicit **Save without drawings** button (`:441-449`): it sets `forceValuesRef` and re-runs the save through the values-only serializer `serializeWorkbookBytes` (`univerSerialize.ts:41`, called at `ExcelViewer.tsx:172-173`). No silent rewrite of a structurally edited package is attempted; the user confirms the loss of drawings.
- **Hash contract.** `expected_hash` and the server's check compare the same value: lowercase hex SHA-256 of the exact bytes. The client side is `rawContentHash` in `univerSerialize.ts` (`univerSerialize.ts:25`, `@noble/hashes` `^1`, pure JS, so it works on plain-http origins). The server side is `rawContentHash` in `handler_files.go` (`handler_files.go:1709-1711`, `crypto/sha256`). A 409 therefore means the bytes on disk differ from the bytes the viewer last loaded or saved.
- **Failure.** The error shows in a `role="alert"` span (`ExcelViewer.tsx:440`) and is logged with `console.error` (`:203`). `savedRevision` is not advanced, so the workbook stays dirty. A 409 appends `Reload the file and re-apply your edits.` (`:196`); a structural guard hit appends the values-only hint (`:199`).
- **`onSave` override.** A caller can pass `onSave` to replace the built-in request (`ExcelViewer.tsx:165-166`). It goes through the same `savedRevision` and error handling.
- **First-save confirmation and date-edit gate.** `requestSave` (`ExcelViewer.tsx:246-260`) saves at once for a file already confirmed this session (`confirmedSaveKeys`, `:24`, keyed by host, root and path at `:175`), so a remount does not ask again — **unless a date edit is detected**. `requestSave` calls `hasDateLikeEdit(baselineRef.current, host === null ? null : host.snapshot())` (`:247`; helper at `:51-69`, a date regex over cell values that changed between the baseline and live snapshots) and opens the dialog even for a confirmed file when it returns true (`:250`). Otherwise it opens a ConfirmDialog, `Save spreadsheet?` (`:528-560`, description at `:531-533`), and returns a promise that settles with the user's answer: the save's result after Save, `false` after Cancel. A second request while the dialog is open gets the same promise (`confirmRef`, `:127`), so every caller sees the real outcome. Unmounting the viewer settles a waiting request with `false` (`:264-270`). The dialog states that drawings and images are kept but formulas, charts, pivot tables, number formats and some styles may still change and names the `.bak` (`:533`). When a date edit is detected it also renders the **"I understand edited dates become text"** checkbox (`:534-544`, text at `:542`) and passes `confirmDisabled={dateEditDetected && !dateAcknowledged}` (`:549`; the prop disables the confirm button at `ConfirmDialog.tsx:105`), so Save stays disabled until the user checks the box — the date-type loss is now an explicit acknowledgement, not just a caveat.
- **Files-tab entry points.** The Files-tab toolbar has its own Save button (`web/src/components/Files/FileTabContent.tsx:293-303`, disabled unless dirty at `:297`). Cmd/Ctrl+S is a window keydown listener (`:129-135`) that acts only while the tab is `props.active` and dirty. Both call the handler the viewer hands up through `onSaveRef` (`ExcelViewer.tsx:258-265`), which is `requestSave`, so the first-save confirmation gates every entry point. `FileTabContent.tsx:326` passes the ref down. An in-flight save is joined, not repeated (`ExcelViewer.tsx:155-156`), so the App's Cmd/Ctrl+S (which also saves the active tab) and the tab's own listener can both reach the viewer on one keypress and send one PUT.
- **What gets written.** The default save patches only changed cells into the original package, so untouched cells keep their original XML — including formatted numbers and dates whose raw `<v>` differs from their displayed text — and drawings/media/styles/shared strings are preserved. An edited cell is written from the loader's display-text snapshot, but `valueWrite` (`xlsxPackagePatch.ts:267`) takes the original `<c>` type: an originally numeric cell (no `t`, or `t="n"`) whose edited text parses back to a finite number (commas/whitespace stripped by `numericFromDisplay`, `xlsxPackagePatch.ts:260`) is written as a numeric `<v>` with no `t`, and an originally boolean cell (`t="b"`) whose text is TRUE/FALSE/1/0 stays `t="b"` with `<v>1</v>` or `<v>0</v>`. Edited DATE cells remain lossy: the loader discarded the raw serial, so the displayed date is written as text — the default save now gates that loss behind the explicit date-acknowledgement checkbox in the first-save dialog (see First-save confirmation). The values-only fallback (`serializeWorkbookBytes`, `univerSerialize.ts`) writes values, formulas that exist in the Univer snapshot, column widths and merges; it writes no styles and cannot preserve drawings.

### Close confirm (Save / Discard / Cancel)

- **Dirty check.** `requestCloseTab` (`useEditorTabs.ts:592-603`) looks up the tab and, when `tab.isDirty` is set, opens `ConfirmCloseDialog` through `pendingClose` (`:597`) instead of closing. Excel preview tabs reuse the same dialog and the same `pendingClose` state as Monaco editor tabs; a clean tab closes immediately.
- **Save delegates to the registered handler.** `saveEditorTab` (`useEditorTabs.ts:605-677`) routes every preview-only tab (Excel, PDF, DOCX and the other viewer-only kinds) to the handler registered for its tab id (`:630-652`), not `api.saveFileContent`, because `tab.content` is `""` for a preview-only tab. A dirty tab with no registered handler throws (`:639`); a clean tab with no handler is a no-op (`:638`). For Excel the handler is `invokeExcelSave` from `FileTabContent` (`web/src/components/Files/FileTabContent.tsx:105-109`), which calls the viewer's current save through `excelSaveRef` at call time and throws when the viewer is not mounted (`:106-107`). The viewer's `requestSave` returns `Promise<boolean>`: `true` when the bytes were written, `false` when the save failed or the first-save confirmation was cancelled. Every entry point shares it, so the close dialog's Save, the toolbar Save button and Cmd/Ctrl+S behave identically. On an unconfirmed file the close dialog's Save waits for the first-save answer; on Save it writes and closes the tab, and on Cancel `saveEditorTab` throws `Save failed or was cancelled` (`useEditorTabs.ts:642`), which the close dialog shows while the tab stays open.
- **Success.** The tab closes. `isDirty` is cleared, `diffVersion` is bumped (the diff and print surfaces re-read), the draft is cleared and the quit guard is disarmed (`useEditorTabs.ts:643-651`, the disarm at `:649`).
- **`false` or a thrown error.** `saveEditorTab` throws `Save failed or was cancelled` (`useEditorTabs.ts:642`) and sets `saveError`; `confirmSaveAndClose` catches it and leaves both the tab and the dialog in place (`:690-693`). The guard stays armed, so a later quit still prompts, and the user can retry, Discard or Cancel.
- **Discard** closes without saving (`confirmDiscardAndClose`, `:696-701`) and clears the guard. **Cancel** only clears `pendingClose` and `saveError` (`cancelClose`, `:703-706`); the tab and its grid edits stay.
- **Handler lifecycle.** `FileTabContent` registers `invokeExcelSave` in an effect keyed by the tab id (`FileTabContent.tsx:114-120`), so it registers once per tab, and unregisters it on unmount (`:118`), so a stale handler never outlives its tab. `invokeExcelSave` reads `excelSaveRef.current` each time it runs (`:105-108`), so the viewer can replace its save closure on every edit without re-registering.

### Quit guard

- Dirty Excel tabs arm the desktop unsaved-draft quit guard through the existing tab-dirty path. `setTabDirty` (`useEditorTabs.ts:565-582`) calls `noteDraftPersistPending(id, tab.path)` when dirty (`:580`) and `noteDraftPersistSuccess(id)` when clean (`:581`). The state updater returns the previous list when the flag is unchanged; the guard call sits outside it, because React may run an updater twice and the guard is module-level state.
- The guard reconciles from tab dirtiness (`reconcileDraftGuard(editorTabs.filter((t) => t.isDirty).map((t) => t.id))`, `useEditorTabs.ts:423`), so Excel tabs are included without a separate registry: it arms while grid edits live only in memory and clears on save, discard or close.
- `FileTabContent` reports the grid's dirtiness up with `onDirtyChange` (`FileTabContent.tsx:97-100`, passed at `:325`), so the tab's `isDirty` is the single value both the close confirm and the quit guard read.
- The desktop-shell side (blocking quit and the "Keep editing / Quit anyway" prompt) is unchanged; see [Desktop quit guard for unsaved drafts](../gotchas/desktop-quit-guard-and-sticky-port-fallback.md).

## Raw save endpoint (`PUT /api/files/raw`)

The route is `PUT /api/files/raw` behind `authMiddleware` (`internal/server/server.go:504`). A local project uses `HandleSaveFileRaw` (`internal/server/handler_files.go:1737`). A remote project (`?host=`) uses `remoteSaveFileRaw` (`internal/server/handler_remote_files.go:647`). Both apply the same checks in the same order.

**The client always calls this local route, never the proxy prefix.** `apiClient.saveFileRaw` (`web/src/api/client.ts:3843`) builds `PUT /api/files/raw?path=…&project_root=…&expected_hash=…[&force=1][&host=…]` on its own origin; a remote project's `host` rides in the query (`:3852`), so `HandleSaveFileRaw` dispatches to `remoteSaveFileRaw` on `hostParam(r)` (`handler_files.go:1739-1741`). It must not be routed through `/api/remote/{host}/api/files/raw`. That proxy's admission resolves the project identity from `?project=` or `?path=`, then the `X-Ocode-Project` header, then `?project_path=`, then a POST body `project_path` (`resolveProjectPath`, `internal/server/handler_remote_proxy.go:272`), and it never reads `?project_root=`. For a raw save `?path=` is the FILE and `?project_root=` is the project, so the proxied form resolved the file path as the project and always answered 403 `unknown host or unregistered project path` (`handler_remote_proxy.go:79`). **Rule:** a call routed through `/api/remote/{host}` must carry the project identity in `?project=`, `X-Ocode-Project` or `?project_path=`; an endpoint that already has a local `?host=` remote branch (file read, save and access checks) uses that branch instead of the proxy. `?path=` is ambiguous — it is the project path only on `/api/projects/sessions`.

- **Body.** `application/octet-stream`, or no Content-Type. Any other type is a 400 (`handler_files.go:1751-1758`). The body is read by `readRawSaveBody` (`handler_files.go:1718`) under a 32 MiB cap (`previewRawMaxBytes`, `handler_files.go:1186`). Only an over-cap body is a 413. Any other read failure is a logged 400.
- **Query.** `path`, `expected_hash`, `force` (`1` or `true`, `handler_files.go:1759-1760`). `project_root` is required for remote saves (`handler_remote_files.go:665-667`).
- **Extension.** Only `.xlsx`, `.docx` and `.pdf` (case-insensitive, `rawSaveAllowedExt` in `internal/server/raw_save_ext.go`), checked on the resolved target path. `.docx` and `.pdf` are there for the in-app Word and PDF editors, per the comment at `handler_files.go:1798-1800`. Anything else is a 400 (`handler_files.go:1801-1804`; remote `handler_remote_files.go:682-685`).
- **Containment.** Local: `writeScopeRoot` picks the root (`handler_files.go:1762`), then the target's parent is resolved through symlinks and must sit inside the real root (`:1787-1797`). Remote: lexical containment by `remoteRelCheck`, then `remoteDirInside` (`handler_remote_work.go:205`, called at `handler_remote_files.go:690`) checks the parent's realpath.
- **Symlink refusal.** A symlinked final component is refused before anything is read or written. Local: `handler_files.go:1817-1829`. Remote: `remoteLstatKind` (`handler_remote_files.go:806`), called at `:716`, refuses at `:722-724`.
- **Hash.** `expected_hash` is the lowercase hex SHA-256 of the exact stored bytes (`rawContentHash`, `handler_files.go:1709-1711`). A missing target hashes as `__missing__` (`rawMissingHash`, `handler_files.go:1699`). A mismatch is a 409 (`handler_files.go:1847-1856`; remote `handler_remote_files.go:742-750`). The text save's `hashContent` is a different function and is never used for raw saves.
- **Requirement.** When the target exists and `force` is not set, an empty `expected_hash` is a 400 (`handler_files.go:1843-1846`; remote `handler_remote_files.go:738-739`). A missing target can be created without a hash.
- **Existing bytes are always read.** The `.bak` needs them, so they are read on every save, even with `force=1`. Local: `handler_files.go:1834-1840`. Remote: `handler_remote_files.go:727-735`, where a read failure (including a transport error) is a 502, never treated as a missing file.
- **One-time `.bak`.** Before the rename, the pre-existing bytes are written to `<path>.bak`, but only after every containment and symlink check has passed (local `handler_files.go:1915-1937`). The `.bak` path is Lstat'ed first (`:1920`). A symlink there is a 400 (`:1926-1929`). A stat failure is a logged 500 locally (`:1921-1925`) and a 502 remotely (`handler_remote_files.go:758-761`). The backup is written only when no `.bak` exists (`handler_files.go:1930`), so an existing `.bak` is never overwritten and holds the bytes from before the first raw save. A backup write failure aborts the save with a logged 500 (`handler_files.go:1931-1935`; remote `handler_remote_files.go:768-773`).
- **Permissions.** Local: the temp file takes the existing file's permission bits, and a new file gets `0600` (`handler_files.go:1897-1909`). Remote: `remoteWriteFileAtomic` copies an existing file's mode onto the temp file with `cp -p`, and a new file keeps `mktemp`'s `0600` (`handler_remote_files.go:784-800`, called at `:769` and `:777`).
- **Write.** Local writes to a temp file in the same directory and renames it over the target (temp at `handler_files.go:1860`, rename at `:1939`), so the write is atomic. The local temp file is fsynced before the rename (`handler_files.go:1874-1877`); the remote helper does not fsync (see TODO.md, review follow-ups round 2). Remote does the same in one remote command (`remoteWriteFileAtomic`, `handler_remote_files.go:792-800`, called at `:777`): `mktemp` makes the temp file in the target's directory (`:795`), `cp -p` copies an existing target's mode onto it (`:796`), the bytes stream in through `remoteWriteStdin` (`handler_remote_work.go:954`), a `wc -c` check must equal the byte count, and `mv -f` renames it over the target (`handler_remote_files.go:797`). Every failure path removes the temp file and leaves the target as it was, so a stdin stream cut short cannot install a truncated file. The one-time `.bak` uses the same helper. `remoteWriteFile` (`handler_remote_work.go:947`) still uses `cat >` for the gitignore and text saves; raw saves do not use it.
- **Response.** `{"path": …, "saved": true}`.

## Removed

The old DOM grid's selection toolbar (Copy, Ask LLM) and its column-resize drag are gone. Univer's canvas grid replaces them, so selecting cells does not offer Copy or Ask LLM.

## Known gaps

- **Known data loss on an edited DATE cell (now gated by explicit acknowledgement): the loader keeps display text only.** `excelJsCell` (`web/src/components/Preview/univerData.ts:312`) stores each cell's formatted string as Univer text (`v: string`, `t: STRING`) and nothing else, so the raw serial is gone. In the default baseline-diff save, UNEDITED cells keep their original XML byte-for-byte, and an EDITED numeric or boolean cell keeps its stored type: `valueWrite` (`xlsxPackagePatch.ts:267`) takes the original `<c>` `t` attribute (passed at `xlsxPackagePatch.ts:491`), so an originally numeric cell (no `t`, or `t="n"`) whose edited text parses back to a finite number (commas/whitespace stripped by `numericFromDisplay`, `xlsxPackagePatch.ts:260`) is written as a numeric `<v>` with `t` removed (`1,234.50` edited to `2,000.75` → `<v>2000.75</v>`), and an originally boolean cell (`t="b"`) whose text is TRUE/FALSE/1/0 stays `t="b"` with `<v>1</v>` or `<v>0</v>`. An EDITED DATE cell is still lossy: its displayed date (e.g. `2024-01-15`) does not parse as a number, so it falls through to an inline string. This loss is now **gated at save time**: `hasDateLikeEdit` (`ExcelViewer.tsx:51-69`, called from `requestSave` at `:247`) compares the baseline and live snapshots, forces the first-save dialog open even on an already-confirmed file (`:250`), and the dialog disables Save (`confirmDisabled`, `:549`; applied at `ConfirmDialog.tsx:105`) until the user checks the "I understand edited dates become text" box (`:534-544`). A formula's edited cached result follows the same rule (numeric when parseable, else text). The `KNOWN LOSS` assertions in `web/src/components/Preview/univerSerialize.test.ts` (`:123-130`) pin the values-only serializer used by the fallback, which still writes edited values as text. The open work, including the decision on blocking or warning on save for workbooks with formulas, is in [TODO.md](../../TODO.md) under "review follow-ups round 2".
- **Values-only fallback loses drawings.** The explicit "Save without drawings" path writes values, formulas present in the Univer snapshot, column widths and merges, but no styles and no drawings. Formulas the loader discarded, number formats, styles, charts and pivot tables are never carried into the grid, so neither save path can restore them. Structural edits (sheet list/order, rowCount, columnCount, mergeData) force this fallback with an explicit user confirmation.
- **Overlay images stay view-only.** They cannot be selected or moved, their size comes from the anchor, so a two-cell image can differ in aspect from Excel (see Floating images), and they are anchored to fixed cell coordinates that do not follow row insert/delete.
- **Capped sheets are read-only.** A sheet over 50000 rows or 200 columns shows only its first rows and columns, and the workbook cannot be saved while any sheet is capped.
- **Force-save is not offered for preview-only tabs.** `saveEditorTab` ignores `force` on that branch (`useEditorTabs.ts:630-652`), and the viewer always sends its own base hash, so there is no forced-overwrite path. No UI reaches it today; the gap is tracked in `TODO.md`.
- **`.xlsm` reaches the viewer, read-only.** The routing gates that once excluded it are now permissive: `kindByExt` maps `.xlsm` to `excel` (`web/src/lib/previewKind.ts:59`), `previewRawTypes` lists it (`handler_files.go:1229`), and `OOXML_WORKBOOK` accepts it (`univerData.ts:516`). The viewer edits only `.xlsx` (`ExcelViewer.tsx:143-144`), and the raw save refuses it. Whether ExcelJS loads a macro-enabled package was not checked for this page.
- **Horizontal `fill` alignment renders left (approved known gap).** Excel's `fill` repeats the cell's content across the column width. Univer's `HorizontalAlign` enum has no fill member, so `HORIZONTAL_ALIGN` maps `fill` to `LEFT` (`xlsxStyle.ts:165-166`). The user approved this substitution on 2026-11-03; the comment at `xlsxStyle.ts:165` records the approval.
